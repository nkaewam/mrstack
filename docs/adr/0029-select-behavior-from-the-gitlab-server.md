# Select behavior from the GitLab server

`mrstack doctor` will query the authenticated instance through `glab api version` and choose legacy mode below GitLab 19.1 or native mode at 19.1 and later. Legacy mode derives relationships and performs post-merge retargeting; native mode delegates visualization and automatic retargeting to GitLab while `mrstack` still derives the chain needed for restacking, health tracking, conflict remediation, and agent integration. Both modes enforce GitLab 19.1's maximum stack depth of ten for consistent migration behavior. If version detection is unavailable, the tool refuses to guess and requires the global `--gitlab-mode legacy|native` override; `auto` remains the default. When the version is readable, an explicit mode must agree with detection or the invocation fails before observation or mutation.

In native mode, a successor that still targets a uniquely merged predecessor returns `waiting/native_retarget_pending`; `mrstack` never races GitLab with its own target update. The external agent owns retry limits and escalates a persistent condition to the user for manual GitLab repair. Once GitLab changes the relationship, the next check consumes that topology normally.
